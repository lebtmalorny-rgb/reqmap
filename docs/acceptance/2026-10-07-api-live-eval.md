## Причина пропущенных подтверждений

В исходном proposal первого атома выбран верный `P-NOVA-VM-CREATE`,
`E-NOVA-VM-CREATE` и `POST /servers`. Однако `role_ru` равен исходному требованию:

```json
{"role_ru":"Nova должна создавать ВМ через API",
 "supported_aspects":["Nova должна создавать ВМ через API"]}
```

[Проверка mapping](../../src/reqmap/mapping.py) требует присутствия каждого
значимого слова роли в corpus процитированного specific evidence и capability.
Слово «должна» отсутствует в этом corpus и не входит в список служебных слов.
Поэтому нижний validator понижает mapping до insufficient, а source binding
показывает следствие `EVIDENCE_MISSING` / `prior_status`. Реальная причина
не отражена отдельной диагностикой поля `role_ru`.

Все 17 пропущенных подтверждений воспроизведены независимо из фактических
proposals клиента. Для всех них единственное отсутствующее слово роли —
«должна». В локальном повторе заменены только `role_ru` на `claim_ru` выбранного
evidence и согласованный с ролью `supported_aspects`. Например:

```json
{"role_ru":"Nova документирует создание вм через API POST /servers.",
 "supported_aspects":["Nova документирует создание вм через API POST /servers."]}
```

С теми же исходными атомами, evidence, predicates, endpoint, KB и validator
получены **18/18 supported**. Этот повтор — диагностика общего backend;
он не является вторым живым прогоном модели. Завершённая MCP-сессия и её пять
артефактов не изменялись, исходные модальные слова из требований не удалялись.

## Следующая работа и границы

Следующий узкий шаг — устранить разрыв контракта описания роли: явно объяснить
агенту правила `role_ru`/`supported_aspects`, выдавать конкретную диагностику
неподтверждённых слов и проверить корректировку proposal. После изменения
повторить тот же frozen набор настоящим клиентом с новой сессией, сохранив
первый результат для сравнения. Не менять ожидания и не ослаблять проверку
исходных условий ради увеличения числа supported.

Этот прогон подтверждает интеграцию, сохранность входа и fail-closed поведение
на восьми контрастах, но не готовность предметного сопоставления к эксплуатации.
Широкий этап 5, negative/conflict/ambiguity suites, private XLSX, PyCharm/Linux
и дополнительные семейства этапа 4 остаются открытыми.
