Строки 1–12 подтверждают создание, чтение, переименование `name` и удаление
пользователя, проекта и роли. Строки 27–28 проверяют составное требование и
два одинаковых обязательства. Четырнадцать контрастов не получили положительного
статуса: время, GUI, отказ, отрицание, LDAP/AD, пользователь гипервизора,
обход прав, назначение роли, произвольный backend, неверный сервис, другой
релиз, отправка SMS, injection и неуказанный контур пользователя.

Девять нераспознанных формулировок сохранены целиком с `SOURCE_UNPARSED` и
`BINDING_UNREVIEWED`. Остальные контрасты получили диагностику недоказанного
условия, интерфейса, направления либо actor. `insufficient_evidence` здесь
означает отсутствие доказательства полного обязательства; это не утверждение
о невозможности соответствующей функции в OpenStack.

В журнале клиента **108 успешных MCP-вызовов**: start 1, get_session 1,
submit_atoms 28, get_atom_context 30, search_knowledge 13, get_evidence 3,
submit_mapping 30, finalize 1, get_result 1. Финализация вызвана с
`allow_partial=false`; затем клиент получил результат через MCP.
Отдельная независимая read-only проверка не входит в эти 108 вызовов.

Аудит остальных вызовов нашёл семь shell-команд: чтение трёх навыков, входного
TXT и manifest, затем две проверки новых файлов и исходных цитат. Чтений
fixture с ожиданиями, тестов, исходного кода, старых отчётов или git history
в вызовах клиента нет. Инфраструктура, `reqmap analyze` и отдельный endpoint
модели не запускались. Сопоставления предложены моделью через MCP и приняты
общим backend; независимый проверочный скрипт только прочитал готовый результат.
