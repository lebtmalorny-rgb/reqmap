Подключение и полный цикл анализа через чат IDE подтверждены. Настоящий агент
прочитал skill, вызвал все девять MCP-инструментов reqmap и получил пять файлов
через `reqmap_finalize` и `reqmap_get_result`. Оба исходных обязательства сохранены.

Предметная проверка `MULTI` не совпала с ожиданием контрольного набора:
ожидался `supported`, получен `insufficient_evidence` для обоих атомов.
Поэтому результат подтверждает работу интеграции, но не готовность всего
контрольного набора или качество анализа произвольных требований.

## Расхождение с контрольным ожиданием

Для первого атома модель предложила `supported`, но сервер вернул
`insufficient_evidence` с диагностикой «Статус понижен: отсутствует достаточное
официальное evidence». Для второго атома модель уже предложила
`insufficient_evidence`, сославшись на этот результат проверки.

Проверка по фактическим данным и [mapping.py](../../src/reqmap/mapping.py)
установила две причины непрохождения grounding:

1. В proposal указано `api_operation="server"`. Это значение прямо входит в
   `_GENERIC_RUNTIME_OPERATIONS` и не считается доказанной API-операцией.
2. `role_ru` и `action_ru` не прошли `_semantic_text_grounded`: проверка требует
   наличия каждого значимого слова в корпусе полей cited evidence и capability.
   Общее описание Nova и REST API из `E-NOVA-SCOPE-001` не покрывает все слова
   этих формулировок.

Наличие официального evidence ID само по себе не удовлетворяет этим правилам.
Объяснение второго атома про недостаточность evidence — интерпретация модели;
точные причины первого понижения установлены отдельно по валидатору.

Ожидание `supported` в frozen eval оставлено без изменений. Требуется отдельно
согласовать достаточность учебной базы, допустимые proposals и критерии
контрольного примера. В этой проверке валидатор и KB не менялись.

Последующий [аудит покрытия](2026-10-05-requirements-coverage-audit.md) выявил
обратный случай: полное название capability в поле операции позволяет получить
необоснованный `supported`. Поэтому исправление включает проверку связи
исходного обязательства с evidence, а не только пополнение базы Nova.
