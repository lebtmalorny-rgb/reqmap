## Аудит и проверка результата

В журнале **86 успешных MCP-вызовов**, восемь из девяти tools:
start 1, get_session 2, submit_atoms 25, get_atom_context 26, get_evidence 4,
submit_mapping 26, finalize 1, get_result 1. `search_knowledge` не понадобился.
На каждый атом отправлено одно mapping proposal, без повторной подгонки.
Агент сформировал выбор по контекстам MCP; обёртки вызовов на JavaScript
использовались для передачи его предложений через реальные tools.

По аудиту вызовов агент читал skill, вход, общие инструкции/память и новые
готовые артефакты. Чтения tests/контрольных ожиданий или прошлых отчётов нет.
Нет инфраструктурных вызовов, отдельного LLM endpoint, `reqmap analyze` либо
редактирования кода, KB и настроек. В каждом положительном proposal `role_ru`
равен `claim_ru` выбранного доказательства; полный `source_quote` сохранён.

Независимая сверка JSON с frozen fixture проверила все строки, порядок,
координаты, обязательность, ordinal, точные цитаты и spans, source hashes,
статусы, выбранный predicate для каждого положительного атома и сохранённые
непокрытые части контрастов. Все 25 исходных текстов и 26 atom IDs найдены в XLSX.
Хеши файлов пересчитаны и совпали с manifest; отдельный read-only
`reqmap_get_result` успешно проверил finalized-комплект.

Строки 1–16 и 25 получили `supported`; строка 25 содержит два отдельных
подтверждённых атома. Строки 17–24 сохранили `insufficient_evidence`:

- 20: `SOURCE_DIRECTION_UNPROVEN` — возможность удаления не доказывает запрет.
