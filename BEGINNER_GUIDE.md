# Установка и запуск агента reqmap в VS Code и PyCharm

Инструкция для Linux и macOS: установим программу, подключим её инструменты
к чату IDE и получим отчёт по требованию OpenStack 2025.1.
Терминал понадобится для установки; диалог с агентом идёт во встроенном чате.

Codex и OpenCode — программы-клиенты агента. Модель выбирается внутри клиента:
она читает задачу и предлагает сопоставления. Reqmap проверяет предложения
по локальной базе знаний и создаёт отчёт. Программа не создаёт виртуальные
машины и не меняет серверы.

На 05.10.2026 агентный слой опубликован в `main`, установка и автоматические
MCP-сценарии проверены. В macOS VS Code + Codex выполнен один полный анализ
через чат с экспортом пяти файлов. В контрольном примере обнаружено расхождение
предметного статуса; PyCharm и Linux IDE ещё не проверены. Подробности —
в [отчёте проверки](docs/acceptance/reqmap-ide-agent-layer.md).

## Что нужно подготовить

Нужны Python 3.11 или новее, Git, папка проекта и одна IDE:
[VS Code](https://code.visualstudio.com/download) или
[PyCharm](https://www.jetbrains.com/pycharm/download/).
Выберите один маршрут: VS Code + Codex, PyCharm + Codex или PyCharm + OpenCode.
Преподаватель поможет с учётной записью клиента и доступом к выбранной модели.
Отдельный сервер модели или API-ключ **для reqmap** не нужен.

Интернет нужен для скачивания проекта, IDE и клиента, а также для облачной
модели клиента. Установка Python-библиотек reqmap после скачивания проекта
работает без сети. Это не означает, что облачный чат тоже работает офлайн.

## Шаг 1 Открыть терминал и проверить Python

Терминал — окно, в которое вводят команды. Вставляйте команды по одной и нажимайте
Enter. Строки с результатом выполнения копировать обратно не нужно.

На Mac нажмите Command + пробел, введите `Terminal` и откройте приложение
«Терминал». В Linux откройте приложение «Терминал» через меню программ.
Обычный терминал здесь нужен для первоначальной подготовки компьютера.
После получения проекта перейдём во встроенный терминал выбранной IDE.
Для одинакового поведения команд в обеих системах сначала выполните:

```bash
bash
```

Это переключит текущий терминал на Bash, не меняя системные настройки.
В новом окне терминала повторите эту команду перед работой по инструкции.

Проверьте Python и Git:

```bash
python3 --version
git --version
```

Подходит Python 3.11 или новее, например 3.12. Если нужные программы уже есть,
переходите к шагу 2.

Если их нет, выберите ниже только свою систему. Подготовка системных программ
требует Интернета или доступа к локальному зеркалу пакетов.

### Linux с Rocky Linux 9

Администратор может установить программы так:

```bash
sudo dnf install -y git python3.11 python3.11-pip
python3.11 --version
```

В шаге 3 используйте вариант с `PYTHON_BIN=python3.11`.

### Linux с Ubuntu 24.04

```bash
sudo apt update
sudo apt install -y git python3 python3-venv
python3 --version
```

В шаге 3 используйте обычный `./install.sh`. В Ubuntu 24.04 пакеты
[python3](https://packages.ubuntu.com/noble/python3) и
[python3-venv](https://packages.ubuntu.com/noble/python3-venv) относятся к Python
3.12. Для другого дистрибутива проверьте минимум 3.11 и наличие `venv` с `pip`.

### macOS

Если Python 3.11+ и Git уже установлены, ничего переустанавливать не нужно.
Иначе используйте Homebrew — менеджер установки программ для Mac.
Проверьте его наличие:

```bash
brew --version
```

Если команда не найдена, сначала установите Homebrew по
[официальной инструкции](https://docs.brew.sh/Installation).
Проверьте указанные там требования к вашей версии macOS и выполните команды
из раздела `Next steps`, который покажет установщик. Затем снова проверьте
`brew --version` и установите Python и Git:

```bash
brew install python@3.11 git
python3.11 --version
git --version
```

Эти команды соответствуют официальным страницам
[Python 3.11](https://formulae.brew.sh/formula/python@3.11) и
[Git](https://formulae.brew.sh/formula/git). `sudo` перед `brew install` не нужен.
В шаге 3 используйте вариант с `PYTHON_BIN=python3.11`.

## Шаг 2 Получить проект и открыть его в IDE

Если проекта ещё нет, выполните:

```bash
git clone https://github.com/lebtmalorny-rgb/reqmap.git
cd reqmap
```

Если преподаватель уже передал папку проекта, пропустите скачивание и сразу
откройте эту папку в IDE по инструкции ниже.
В ней должны быть `install.sh`, `config.agent.example.yaml`,
каталоги `knowledge` и `vendor/wheels`.

После скачивания командами выше проверить текущую папку и её содержимое можно так:

```bash
pwd
ls
```

Запомните путь, который показала команда `pwd`. Теперь откройте папку проекта
в одной из двух программ.

### Вариант с VS Code

1. Откройте VS Code и выберите `File → Open Folder`.
2. Выберите папку `reqmap`, где лежит `install.sh`.
3. Для работы с Python установите расширение `Python` от Microsoft через панель
   Extensions. Оно добавляет выбор интерпретатора для редактора.
4. Выберите `Terminal → New Terminal`. Внизу появится окно для команд.

Так работает [встроенный терминал VS Code](https://code.visualstudio.com/docs/terminal/getting-started).

### Вариант с PyCharm

1. На стартовом экране выберите `Open`, либо используйте `File → Open`.
2. Выберите папку `reqmap`, где лежит `install.sh`, и откройте её как проект.
3. Выберите `View → Tool Windows → Terminal`.
4. Пока оставьте выбор интерпретатора на потом: `.venv` создаст installer на шаге 3.

Это [встроенный терминал PyCharm](https://www.jetbrains.com/help/pycharm/terminal-emulator.html).
Используйте именно вкладку Terminal: туда вводятся команды из этой инструкции.

### Проверка внутри IDE

Во встроенном терминале выбранной программы выполните:

```bash
bash
pwd
ls
```

`pwd` должен показать папку проекта, а `ls` — файл `install.sh`.
Если это другая папка, перейдите в папку проекта командой `cd` с её полным путём
в кавычках. **Все следующие команды выполняйте здесь, во встроенном терминале IDE.**
При создании новой вкладки терминала снова выполните `bash` и проверьте папку.

## Шаг 3 Установить программу

Если команда `python3 --version` показала подходящую версию:

```bash
chmod +x install.sh
./install.sh
```

Если на шаге 1 отдельно установлен Python 3.11:

```bash
chmod +x install.sh
PYTHON_BIN=python3.11 ./install.sh
```

Выберите один из этих вариантов. Installer создаст папку `.venv` с программой
и её библиотеками. Установку reqmap запускайте от своего пользователя, без `sudo`.
В конце появится сообщение `Автономная установка reqmap завершена`.

Проверьте результат:

```bash
.venv/bin/reqmap --version
.venv/bin/reqmap knowledge validate --path knowledge/epoxy-2025.1
```

Первая команда выводит версию, например `reqmap 0.1.0`. Вторая должна вывести
`База знаний проверена`. Для этих проверок модель не нужна. Путь `.venv/bin/reqmap`
уже указывает на установленную программу; отдельно «активировать окружение»
в этой инструкции не требуется.

### Выбрать Python для проекта в IDE

Теперь `.venv` существует. Укажите этот же Python редактору.

В **VS Code** нажмите Command + Shift + P на Mac или Ctrl + Shift + P в Linux,
найдите `Python: Select Interpreter` и выберите Python из `.venv` текущего
проекта. Если его нет в списке, укажите файл `.venv/bin/python` через выбор пути.
Подробности — в [инструкции VS Code](https://code.visualstudio.com/docs/python/environments).

В **PyCharm** откройте Settings и найдите `Python → Interpreter`.
Через `Add Interpreter → Add Local Interpreter` выберите существующий Python
из `.venv/bin/python` в папке проекта. Новое окружение создавать не нужно.
Названия пунктов могут немного отличаться между версиями;
[инструкция PyCharm](https://www.jetbrains.com/help/pycharm/configuring-python-interpreter.html)
показывает выбор существующего окружения.

После выбора продолжайте работу во вкладке Terminal. В командах явно указан
путь `.venv/bin/reqmap`, поэтому они используют установленный экземпляр программы.

## Шаг 4 Подготовить настройки агента

В терминале IDE, находясь в корне проекта, выполните:

```bash
cp config.agent.example.yaml config.agent.yaml
pwd
```

Первую команду выполняют один раз, пока своего `config.agent.yaml` ещё нет.
Второй результат — полный путь к папке проекта. Он нужен для подключения чата.
В примере уже выбраны учебная база `legacy` и папки `results/agent-sessions`
и `results/agent-reports`. Адреса сервера модели сюда не вписывайте.

## Шаг 5 Подключить чат

Откройте [инструкцию подключения](CLIENTS_CODEX_OPENCODE.md) и выполните раздел
для своего маршрута. Там есть готовые файлы настроек для копирования.
В VS Code откройте панель Codex; в PyCharm — AI Chat и выберите Codex либо
OpenCode. Войдите в клиент и выберите модель, доступную по вашей учётной записи.
Затем подключите reqmap и начните новый чат в папке проекта.

Попросите: «Прочитай `.agents/skills/reqmap/SKILL.md`. Проверь, доступны ли девять
инструментов reqmap, включая `reqmap_start_session` и `reqmap_finalize`».
Если инструментов нет, сначала исправьте подключение. Обычный текстовый ответ
модели ещё не является проверенным анализом reqmap.

## Шаг 6 Выполнить учебный анализ

Вставьте в чат:

> Используй skill reqmap и MCP-инструменты. Проверь требование:
> «Создание виртуальной машины через Nova REST API».
> Покажи атомы, сопоставь их с доказательствами, выполни reqmap_finalize.
> Верни статус, session_id и ссылки на все пять файлов отчёта.

Агент может задать вопрос, если формулировка неоднозначна. Отвечайте словами;
не нужно вручную писать JSON. Если появляется запрос разрешить инструмент,
проверьте, что это инструмент reqmap для вашего учебного анализа.

## Шаг 7 Прочитать результат

Откройте ссылку `report.md`, затем `result.xlsx`. Файлы находятся в
`results/agent-reports/<UUID>/`; UUID — уникальное имя отчёта.

| Файл | Для чего нужен |
| --- | --- |
| `report.md` | Краткий отчёт и нерешённые вопросы |
| `result.xlsx` | Таблицы требований, атомов и доказательств |
| `result.json` | Полный результат для программ |
| `run.jsonl` | Журнал проверок |
| `manifest.json` | Контрольные суммы файлов |

`SUCCESS` означает завершённую обработку, а не поддержку каждого требования.
Проверьте предметный статус: supported, partial, not_supported,
insufficient_evidence или not_applicable. `PARTIAL` сообщает о незавершённой
работе или gaps; `FAILED` — о неудаче обработки. Если агент предлагает
частичный экспорт, решите вместе с преподавателем, подходит ли такой результат.
Не исправляйте готовые файлы вручную: их контрольные суммы перестанут совпадать.

## Несколько требований, TXT и Excel

Вставьте требования отдельным списком и попросите сохранить все строки.
Для TXT положите файл внутрь папки проекта; одна непустая строка — требование.
Для Excel передайте абсолютный путь к исходному XLSX внутри input_root.
Книга читается без изменения. При неоднозначных колонках преподаватель задаёт
`input_profile` в `config.agent.yaml`; исходный файл остаётся исходным.

## Продолжить после перерыва

Сохраните session_id из ответа. В новом чате напишите:
«Продолжи reqmap-сессию SESSION_ID: прочитай её через reqmap_get_session и
обработай незавершённые требования. Если отчёт уже опубликован, проверь и покажи
результат через reqmap_get_result».

Обрыв связи сам по себе не означает, что последняя операция не выполнилась.
Если сохранился запрос без ответа, агент повторяет его с прежними аргументами
и request_id. После обрыва во время экспорта сначала восстанавливают исходный
reqmap_finalize. Готовые отчёты вручную не исправляют.
Менять исходный текст внутри сессии нельзя:
для новых требований или уточнений агент создаёт новую связанную сессию.

## Обновить установленную копию

Для копии, полученной через `git clone`, завершите текущий анализ и остановите
MCP-сервер reqmap средствами клиента. В корне проекта проверьте изменения:

```bash
git status --short --branch
```

Если вы меняли файлы проекта или работаете в другой ветке, сначала согласуйте
обновление с преподавателем. Для чистой ветки `main` выполните:

```bash
git pull --ff-only
./install.sh
.venv/bin/reqmap agent serve --help
.venv/bin/python -m pip check
```

Если первоначальная установка выполнялась с `PYTHON_BIN=python3.11`, повторите
её тем же способом: `PYTHON_BIN=python3.11 ./install.sh` вместо `./install.sh`.
Установка не editable: одного `git pull` недостаточно для обновления программы
в `.venv`. Если `git pull` завершился ошибкой, сначала разберите её, затем
продолжайте установку.

Сохраните свои `config.agent.yaml`, настройки клиента, сессии и отчёты.
Повторно копировать пример поверх существующей конфигурации не нужно.
Чтобы подключить первый пакет API-доказательств к существующей legacy
конфигурации, добавьте поле `binding_catalog_path` со значением
`knowledge/bindings/epoxy-2025.1-api`, как в `config.agent.example.yaml`.
Этот пакет подтверждает создание, чтение, переименование и удаление ВМ,
сетей, портов и томов через API; [границы пакета](docs/acceptance/2026-10-07-core-api-evidence.md)
не включают GUI и гарантии времени. После обновления создайте новый анализ:
активная сессия прежнего контракта может вернуть `SESSION_CONTRACT_MISMATCH`.
Тот же каталог дополнен [операциями Keystone](docs/acceptance/2026-10-07-keystone-api-evidence.md)
для пользователей, проектов и ролей. Указывайте сервис явно, например:
`Keystone должна создавать пользователя через API`. Такие доказательства
не подтверждают учётные записи гипервизора, LDAP/AD или назначение прав.
Запустите новое MCP-соединение средствами клиента и повторите проверку девяти
инструментов из шага 5. Если проект передан архивом, новую полную поставку
передаёт преподаватель; порядок описан в [INSTALL_OFFLINE.md](INSTALL_OFFLINE.md).

## Если что-то не получилось

- Нет reqmap-инструментов: проверьте полный путь, config и выбранный чат.
- `CONFIG_INVALID`: используйте config.agent.example.yaml для MCP-режима.
- `KNOWLEDGE_CHANGED`: база отличается от начала анализа; нужна новая сессия.
- `REVISION_CONFLICT`: агент должен перечитать состояние сессии.
- `ANALYSIS_INCOMPLETE`: продолжите работу либо явно разрешите частичный отчёт.
- `ARTIFACTS_CHANGED`: файл изменён; не выдавайте его за проверенный результат.

Подробности: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Когда нужен deep и прежний CLI

Начните с `legacy`. `deep` требует подписанную, одобренную базу KBv2 и внешний
список доверенных подписантов; их предоставляет преподаватель. Учебные fixtures
из tests не доказывают возможности реального облака.

Прежняя команда `reqmap analyze` отдельно описана в [RUNBOOK.md](RUNBOOK.md).
Она требует собственный endpoint/config.yaml и не используется в этом маршруте.
