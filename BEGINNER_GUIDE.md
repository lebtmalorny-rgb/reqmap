# Установка и запуск reqmap в VS Code и PyCharm

Это инструкция для первого знакомства с программой. Пройдём путь от скачивания
до отчёта по одному требованию. Инструкция подходит для Linux и macOS.
Работать будем в VS Code или PyCharm: откроем проект, установим программу
и запустим её во встроенном терминале. Подготовка компьютера немного отличается;
команды самого reqmap общие.

`reqmap` помогает ответить на вопрос: «Какой компонент OpenStack отвечает за это
требование и чем это подтверждается?» Вы пишете требование, программа обращается
к модели и проверяет предложенное сопоставление по своей базе знаний. Результат
сохраняется в файлы. Программа сама не создаёт виртуальные машины и не меняет
настройки серверов.

Для первого запуска используем обычный режим `legacy` и базу OpenStack 2025.1,
которая уже есть в репозитории. Расширенный режим `deep` описан в конце.

## Что нужно подготовить

Понадобятся компьютер с Linux или macOS, Python версии 3.11 или новее и папка с проектом.
Также нужна одна установленная среда разработки —
[VS Code](https://code.visualstudio.com/download) или
[PyCharm](https://www.jetbrains.com/pycharm/download/). Если её ещё нет,
скачайте установщик для своей системы с одной из этих официальных страниц.
Устанавливать обе программы не требуется.

Для скачивания проекта нужен Git и доступ к GitHub; после скачивания установка
Python-зависимостей проходит без Интернета.

**Для анализа дополнительно нужен работающий сервер модели.** `install.sh`
устанавливает reqmap, но не скачивает и не запускает нейросеть. У администратора
или преподавателя нужно получить три значения:

| Что получить | Что это значит |
| --- | --- |
| Адрес API, заканчивающийся на `/v1` | Куда программа будет отправлять запросы модели |
| Точное имя модели | Какую модель выбрать на этом сервере |
| Ключ API, если он нужен | Пароль для доступа к серверу модели |

Сервер должен предоставлять OpenAI-compatible API с `/v1/models` и
`/v1/chat/completions`. Это интерфейс программы; адрес страницы чата в браузере
для него не подходит. Сервер может находиться на другом компьютере в учебной
сети. Без сервера модели можно установить reqmap и проверить базу, но выполнить
анализ не получится. Подготовка самого сервера модели — отдельная задача.

## Шаг 1 Открыть терминал и проверить Python

Терминал — окно, в которое вводят команды. Вставляйте команды по одной и нажимайте
Enter. Строки с результатом выполнения копировать обратно не нужно.

На Mac нажмите Command + пробел, введите `Terminal` и откройте приложение
«Терминал». В Linux откройте приложение «Терминал» через меню программ.
Обычный терминал здесь нужен для первоначальной подготовки компьютера.
После получения проекта перейдём во встроенный терминал выбранной IDE.
Для одинакового поведения команд в обеих системах сначала выполните:

```bash
bash
```

Это переключит текущий терминал на Bash, не меняя системные настройки.
В новом окне терминала повторите эту команду перед работой по инструкции.

Проверьте Python и Git:

```bash
python3 --version
git --version
```

Подходит Python 3.11 или новее, например 3.12. Если нужные программы уже есть,
переходите к шагу 2.

Если их нет, выберите ниже только свою систему. Подготовка системных программ
требует Интернета или доступа к локальному зеркалу пакетов.

### Linux с Rocky Linux 9

Администратор может установить программы так:

```bash
sudo dnf install -y git python3.11 python3.11-pip
python3.11 --version
```

В шаге 3 используйте вариант с `PYTHON_BIN=python3.11`.

### Linux с Ubuntu 24.04

```bash
sudo apt update
sudo apt install -y git python3 python3-venv
python3 --version
```

В шаге 3 используйте обычный `./install.sh`. В Ubuntu 24.04 пакеты
[python3](https://packages.ubuntu.com/noble/python3) и
[python3-venv](https://packages.ubuntu.com/noble/python3-venv) относятся к Python
3.12. Для другого дистрибутива проверьте минимум 3.11 и наличие `venv` с `pip`.

### macOS

Если Python 3.11+ и Git уже установлены, ничего переустанавливать не нужно.
Иначе используйте Homebrew — менеджер установки программ для Mac.
Проверьте его наличие:

```bash
brew --version
```

Если команда не найдена, сначала установите Homebrew по
[официальной инструкции](https://docs.brew.sh/Installation).
Проверьте указанные там требования к вашей версии macOS и выполните команды
из раздела `Next steps`, который покажет установщик. Затем снова проверьте
`brew --version` и установите Python и Git:

```bash
brew install python@3.11 git
python3.11 --version
git --version
```

Эти команды соответствуют официальным страницам
[Python 3.11](https://formulae.brew.sh/formula/python@3.11) и
[Git](https://formulae.brew.sh/formula/git). `sudo` перед `brew install` не нужен.
В шаге 3 используйте вариант с `PYTHON_BIN=python3.11`.

## Шаг 2 Получить проект и открыть его в IDE

Если проекта ещё нет, выполните:

```bash
git clone https://github.com/lebtmalorny-rgb/reqmap.git
cd reqmap
```

Если преподаватель уже передал папку проекта, пропустите скачивание и сразу
откройте эту папку в IDE по инструкции ниже.
В ней должны быть `install.sh`, `config.example.yaml`,
каталоги `knowledge` и `vendor/wheels`.

После скачивания командами выше проверить текущую папку и её содержимое можно так:

```bash
pwd
ls
```

Запомните путь, который показала команда `pwd`. Теперь откройте папку проекта
в одной из двух программ.

### Вариант с VS Code

1. Откройте VS Code и выберите `File → Open Folder`.
2. Выберите папку `reqmap`, где лежит `install.sh`.
3. Для работы с Python установите расширение `Python` от Microsoft через панель
   Extensions. Оно добавляет выбор интерпретатора для редактора.
4. Выберите `Terminal → New Terminal`. Внизу появится окно для команд.

Так работает [встроенный терминал VS Code](https://code.visualstudio.com/docs/terminal/getting-started).

### Вариант с PyCharm

1. На стартовом экране выберите `Open`, либо используйте `File → Open`.
2. Выберите папку `reqmap`, где лежит `install.sh`, и откройте её как проект.
3. Выберите `View → Tool Windows → Terminal`.
4. Пока оставьте выбор интерпретатора на потом: `.venv` создаст installer на шаге 3.

Это [встроенный терминал PyCharm](https://www.jetbrains.com/help/pycharm/terminal-emulator.html).
Используйте именно вкладку Terminal: туда вводятся команды из этой инструкции.

### Проверка внутри IDE

Во встроенном терминале выбранной программы выполните:

```bash
bash
pwd
ls
```

`pwd` должен показать папку проекта, а `ls` — файл `install.sh`.
Если это другая папка, перейдите в папку проекта командой `cd` с её полным путём
в кавычках. **Все следующие команды выполняйте здесь, во встроенном терминале IDE.**
При создании новой вкладки терминала снова выполните `bash` и проверьте папку.

## Шаг 3 Установить программу

Если команда `python3 --version` показала подходящую версию:

```bash
chmod +x install.sh
./install.sh
```

Если на шаге 1 отдельно установлен Python 3.11:

```bash
chmod +x install.sh
PYTHON_BIN=python3.11 ./install.sh
```

Выберите один из этих вариантов. Installer создаст папку `.venv` с программой
и её библиотеками. Установку reqmap запускайте от своего пользователя, без `sudo`.
В конце появится сообщение `Автономная установка reqmap завершена`.

Проверьте результат:

```bash
.venv/bin/reqmap --version
.venv/bin/reqmap knowledge validate --path knowledge/epoxy-2025.1
```

Первая команда выводит версию, например `reqmap 0.1.0`. Вторая должна вывести
`База знаний проверена`. Для этих проверок модель не нужна. Путь `.venv/bin/reqmap`
уже указывает на установленную программу; отдельно «активировать окружение»
в этой инструкции не требуется.

### Выбрать Python для проекта в IDE

Теперь `.venv` существует. Укажите этот же Python редактору.

В **VS Code** нажмите Command + Shift + P на Mac или Ctrl + Shift + P в Linux,
найдите `Python: Select Interpreter` и выберите Python из `.venv` текущего
проекта. Если его нет в списке, укажите файл `.venv/bin/python` через выбор пути.
Подробности — в [инструкции VS Code](https://code.visualstudio.com/docs/python/environments).

В **PyCharm** откройте Settings и найдите `Python → Interpreter`.
Через `Add Interpreter → Add Local Interpreter` выберите существующий Python
из `.venv/bin/python` в папке проекта. Новое окружение создавать не нужно.
Названия пунктов могут немного отличаться между версиями;
[инструкция PyCharm](https://www.jetbrains.com/help/pycharm/configuring-python-interpreter.html)
показывает выбор существующего окружения.

После выбора продолжайте работу во вкладке Terminal. В командах явно указан
путь `.venv/bin/reqmap`, поэтому они используют установленный экземпляр программы.

## Шаг 4 Указать адрес и имя модели

При первой настройке создайте рабочую копию конфигурации:

```bash
cp config.example.yaml config.yaml
```

Если `config.yaml` уже настроен, пропустите копирование. Откройте его в дереве
файлов VS Code или PyCharm. Файл имеет расширение `.yaml`, но программа читает его
в формате JSON: сохраните фигурные скобки, двойные кавычки и запятые.

Внутри блока `model` замените два значения:

```json
"base_url": "http://127.0.0.1:8000/v1",
"model": "local-model"
```

Это фрагмент, который нужно найти, а не весь файл. Вместо адреса и `local-model`
впишите значения, полученные от администратора. `127.0.0.1` означает ваш
собственный компьютер: оставлять этот адрес можно только если модель запущена
на нём. Поле `knowledge_path` оставьте равным `knowledge/epoxy-2025.1`.
Сохраните файл: Command + S на Mac или Ctrl + S в Linux.

Если сервер требует ключ, выполните в том же терминале:

```bash
read -r -s -p 'Введите ключ API и нажмите Enter: ' REQMAP_API_KEY
export REQMAP_API_KEY
printf '\n'
```

При вводе ключа символы не отображаются — это нормально. В примере конфигурации
поле `api_key_env` уже равно `REQMAP_API_KEY`. Сам ключ в `config.yaml` не пишите.
В новом терминале его потребуется ввести снова. Если сервер не требует ключ,
пропустите эти команды.

## Шаг 5 Выполнить первый анализ

Вернитесь во вкладку Terminal внутри VS Code или PyCharm и скопируйте туда
весь блок. Агент запускается этой командой; открывать отдельный файл `.py`
и нажимать его кнопку Run для этого не нужно.
Символ `\` в конце строки означает продолжение команды
на следующей строке; после него не должно быть пробелов.

```bash
.venv/bin/reqmap analyze \
  --requirement 'Система должна обеспечивать создание виртуальной машины через API и подключение сети' \
  --config config.yaml \
  --output results/first-run
```

Здесь `--requirement` задаёт текст, `--config` выбирает настройки, а `--output`
указывает папку для результата. Текст в одинарных кавычках можно заменить своим.
Дождитесь завершения: программа сначала проверяет базу и доступность модели,
затем разбирает требование и формирует отчёт.

После завершившегося полного или частичного анализа в `results/first-run`
появятся пять файлов:

| Файл | Для чего он нужен |
| --- | --- |
| `report.md` | Начните с него: текстовый отчёт, открывается обычным редактором |
| `result.xlsx` | Таблицы для просмотра в Excel или LibreOffice Calc |
| `result.json` | Полные данные для программной обработки |
| `run.jsonl` | Журнал, который помогает найти причину ошибки |
| `manifest.json` | Сведения о запуске и контрольные суммы файлов |

В дереве проекта откройте `results → first-run → report.md`.
Так отчёт можно прочитать прямо в VS Code или PyCharm. Ещё один способ —
вывести его во встроенном терминале:

```bash
cat results/first-run/report.md
```

Если остались только `run.jsonl` и `manifest.json`, предварительная проверка
не прошла. Откройте журнал и раздел с ошибками ниже.

## Шаг 6 Понять результат

У отчёта есть два разных вида статусов. **Статус запуска** отвечает на вопрос,
удалось ли провести анализ:

| Статус | Значение |
| --- | --- |
| `SUCCESS` | Анализ завершён по правилам выбранного режима |
| `PARTIAL` | Результат частичный; прочитайте перечисленные причины |
| `FAILED` | Запуск не удалось нормально завершить |

`SUCCESS` не означает, что все требования поддерживаются.
**Статус требования** показывает, что удалось подтвердить по базе:

| Статус | Значение |
| --- | --- |
| `supported` | Есть подтверждение поддержки |
| `partial` | Подтверждена только часть требования |
| `not_supported` | Есть прямое доказательство отсутствия поддержки |
| `insufficient_evidence` | Доказательств недостаточно; это не равнозначно отсутствию функции |

Результат примера зависит от модели и доказательств. Сначала прочитайте
объяснение и ссылки на evidence — записи с доказательствами. Сам по себе
красивый ответ модели не подтверждает функцию. В режиме `legacy` завершённый
анализ может иметь `SUCCESS` и отдельные требования с `insufficient_evidence`.

## Как проверить несколько требований

Создайте в папке проекта обычный текстовый файл `requirements.txt` в кодировке
UTF-8. Каждое требование пишите с новой строки. Например:

```text
Система должна обеспечивать создание виртуальной машины через API и подключение сети
Система должна поддерживать Квантовый режим X
```

Второе требование специально выдумано: на нём удобно посмотреть, как программа
показывает отсутствие доказательств. Запустите:

```bash
.venv/bin/reqmap analyze --stdin --text-mode lines \
  --config config.yaml \
  --output results/list-run < requirements.txt
```

Для каждой новой работы выбирайте новое имя папки результата. Чтобы продолжить
тот же запуск после сбоя, повторите исходную команду с теми же входными данными,
настройками и папкой. Программа проверит сохранённые промежуточные результаты
и сможет использовать завершённые записи. Простое повторение не добавляет
в базу отсутствующие доказательства.

## Как загрузить таблицу Excel

Для первого опыта создайте файл `requirements.xlsx` с одним листом. В первой
строке поставьте заголовки `ID` и `Требование`, ниже — данные:

| ID | Требование |
| --- | --- |
| 1 | Создать виртуальную машину через API |
| 2 | Подключить сеть к виртуальной машине |

Используйте именно формат `.xlsx`, а в ячейках требований — обычный текст.
Сохраните книгу в папке проекта и выполните:

```bash
.venv/bin/reqmap analyze requirements.xlsx \
  --config config.yaml \
  --output results/excel-run
```

Такие заголовки программа определит автоматически. Исходная книга остаётся
неизменной; результат находится в `results/excel-run/result.xlsx`.

## Если что-то не получилось

| Что видно | Что проверить |
| --- | --- |
| `python3: command not found` или версия ниже 3.11 | Вернитесь к шагу 1; нужен подходящий Python |
| Ошибка `venv` или `ensurepip` | Администратор должен установить поддержку `venv` и `pip` для выбранного Python |
| `brew: command not found` на Mac | Завершите установку Homebrew и его `Next steps` из шага 1 |
| Ошибка `read: -p: no coprocess` на Mac | Выполните `bash`, затем повторите команды ввода ключа |
| `SyntaxError` после вставки команды | Откройте вкладку Terminal; команды оболочки не вводятся в Python Console |
| `install.sh` или `.venv/bin/reqmap` не найден | Выполните `pwd` и `ls`; вы должны находиться в папке проекта |
| Ошибка о недостающем wheel | Нужна полная копия проекта с `vendor/wheels`; получите её заново |
| `CONFIG_INVALID` | Проверьте кавычки, запятые и скобки в `config.yaml` |
| Соединение отклонено или истекло время ожидания | Проверьте адрес модели, её запуск и доступ к учебной сети |
| Ошибка `401` | Сервер не принял ключ; проверьте его ввод в этом терминале |
| Модель не найдена | Значение `model` должно точно совпадать с именем на сервере |
| Ошибка о `response_format` | Уточните у администратора, нужно ли выставить `supports_response_format` в `false` |
| Модель вернула некорректный JSON | Передайте журнал администратору; модель должна соблюдать формат ответа |
| Неоднозначные заголовки XLSX | Начните с одного листа и двух точных заголовков из примера |
| `PARTIAL` или `insufficient_evidence` | Прочитайте причины в отчёте; переустановка обычно не добавляет недостающих доказательств |

Для помощи сохраните текст ошибки, свою команду запуска без ключа и файл
`run.jsonl`. Подробный разбор есть в [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Когда нужен режим deep

В `deep` программа отдельно описывает ответственность OpenStack, Kolla-Ansible
и операционной системы, а также связи и шаги процедур. В этом режиме
обязательный атом без доказательств или пробел процедуры делает запуск `PARTIAL`.

Одного изменения `analysis_profile` на `deep` недостаточно. Администратор должен
подготовить базу схемы v2 со статусом `approved`, подписанный manifest, отдельный
доверенный файл `allowed_signers` и системный `ssh-keygen` с поддержкой `-Y`.
Полная предметная база для deep в эту поставку не входит. Тестовые примеры
служат для проверки кода и не заменяют такую базу.

После подготовки используйте раздел о deep в [RUNBOOK.md](RUNBOOK.md).
Для переноса программы на компьютер без Интернета есть
[INSTALL_OFFLINE.md](INSTALL_OFFLINE.md).
